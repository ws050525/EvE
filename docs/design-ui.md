# EVE UI 设计稿（v0.5）

> 目标：一个聊天窗口 + 一个会呼吸的莫比乌斯环 + 一个会汇报的悬浮球。
> 关键词：**简洁、克制、高级**。不靠花哨，靠留白、对比和动效节奏。

---

## 0. 三条设计原则

1. **一屏只有一个焦点。** 空态时焦点是莫比乌斯；对话时焦点是文字；执行时焦点是悬浮球。其余全部退到背景里。
2. **光只给一处。** 整个界面只有莫比乌斯环会发光，其他元素用亮度层级区分，不用阴影和描边堆叠。
3. **不假装知道。** 进度只报"已经发生的事"和"正在做的事"，**不画假进度条、不预填未来步骤**。虚假的百分比最伤信任，也最廉价。

## 1. 视觉基调

### 1.1 色板（深色为主）

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 窗口底 | `#0B0D10` | 近黑，微微偏蓝 |
| 面板 | `#12151A` | 比背景亮一级 |
| 气泡/悬停 | `#1A1E25` | 再亮一级 |
| 分隔线 | `#252A33` | 1px，永远不粗 |
| 主文字 | `#E9ECF1` | 不用纯白，纯白太刺眼 |
| 次文字 | `#9BA4B2` | 时间戳、说明 |
| 弱文字 | `#5E6672` | 占位符、禁用 |
| **强调色** | `#5CE1C8` | 青绿。全界面唯一高饱和色 |
| 次级强调 | `#7C8CFF` | 紫蓝，只用于"正在生成"的高光尾迹 |
| 警告 | `#F0B563` | 需要用户确认时 |
| 危险 | `#EF6B6B` | 失败、删除类操作 |

**只用一种强调色**是"高级感"最省力的来源。三个颜色一起亮，就会变成玩具。

### 1.2 字体

- 中文：`Microsoft YaHei UI` → `HarmonyOS Sans SC` → 系统默认
- 西文与数字：`Segoe UI Variable` → `Segoe UI`
- 数字一律等宽（`tabular-nums`），否则时间戳会跳动

| 层级 | 字号 | 行高 | 用途 |
| --- | --- | --- | --- |
| 标题 | 20 | 1.4 | 空态问候 |
| 正文 | 14 | 1.7 | 对话内容 |
| 辅助 | 12 | 1.5 | 时间戳、模型名 |
| 微 | 11 | 1.4 | 气泡副行 |

字号层级**只有四级**，多了就乱。

### 1.3 间距与形状

- 间距序列：`4 / 8 / 12 / 16 / 24 / 32 / 48`
- 圆角：输入框 8、气泡 12、面板 16、球 999（全圆）
- 阴影：**只在悬浮球上用**，`0 0 40 rgba(0,0,0,0.45)`；其余一律不用

### 1.4 图标

线性图标，1.5px 描边，24×24，颜色跟文字层级走。**不用 emoji 当图标**——这是廉价感最大的来源。

## 2. 莫比乌斯环：一个环，七种状态

莫比乌斯环是整个产品的"心跳"，它同时承担三件事：**身份标识、状态指示、等待时的安抚**。

### 2.1 怎么画（避免 3D 的坑）

真 3D 莫比乌斯在 88px 尺寸下会糊成一团，且低多边形旋转会有明显棱角。所以画**2.5D 风格化缎带**：

- 中心线：一个圆，取 240 个采样点
- 带宽：`w(t) = 22 + 3·sin(3t)` 像素（轻微起伏，避免死板）
- 扭转：绕中心线自转 `π·t`，即整圈扭转 180°——这就是莫比乌斯的定义特征
- 投影：整体绕 X 轴倾斜 22°，做出轻微俯视感
- 渲染：两边缘各描一条 path，中间填充竖向渐变；高光是一段沿 t 移动的高斯衰减

这样在任何尺寸下都读得出来，且每帧只有几百个图元，CPU 渲染足够。

### 2.2 状态表

| 状态 | 触发 | 转速 | 亮度 | 附加表现 |
| --- | --- | --- | --- | --- |
| `boot` | 引擎加载中（约 3.7s） | 0.6 rad/s | 0.5→1.0 | 环上有一段弧线随时间生长，**这是真实进度** |
| `idle` | 就绪、无输入 | 0.12 rad/s 往复 | 0.55 | 4s 呼吸，幅度 ±6% |
| `listening` | 语音拾音中 | 0.22 rad/s | 0.8 | 外圈向外脉冲，1.2s 一次 |
| `thinking` | 已发请求、未出首字 | 0.9 rad/s 连续 | 1.0 | 一颗高光粒子沿带面跑，1.8s 一圈 |
| `streaming` | 正在输出文字 | 0.35 rad/s | 0.9 | 高光轻微抖动，幅度随出字节奏 |
| `acting` | 工具执行中 | 0.45 rad/s | 0.95 | 环上 3 个刻度点依次点亮 |
| `error` | 调用失败 | 0 | 0.9→0.4 | 颜色偏红 300ms 后回落，不闪烁 |
| `muted` | 用户静音/最小化 | 0 | 0.25 | 停止一切动效，省电 |

**帧率策略**：`idle` / `muted` 跑 30fps，活跃态 60fps；窗口不可见时直接停表。笔记本电池模式下全程 30fps。

### 2.3 尺寸规则

| 场景 | 直径 |
| --- | --- |
| 空态主视觉 | 220 px |
| 对话进行中的顶栏指示 | 28 px |
| 悬浮球内 | 56 px |

⚠️ 28px 下细节全部丢失，**只保留轮廓 + 状态色**，不要试图显示扭转。

## 3. 三种形态

### 3.1 主窗口（960 × 640，无系统标题栏）

```
┌──────────────────────────────────────────────────────────┐
│  ◍ EVE                    chat ▾            ─  □  ×      │  顶栏 44
├──────────────────────────────────────────────────────────┤
│                                                          │
│                                                          │
│                    ╭──────────────╮                      │
│                    │   莫比乌斯    │  ← 空态 220px 居中    │
│                    ╰──────────────╯                      │
│                                                          │
│                  今天想做点什么？                          │
│                                                          │
├──────────────────────────────────────────────────────────┤
│  ┌────────────────────────────────────────────────┐      │
│  │ 输入…                                          │      │  输入区 88
│  └────────────────────────────────────────────────┘      │
└──────────────────────────────────────────────────────────┘
```

对话开始后，莫比乌斯缩到顶栏左侧 28px 的位置，**主区域完全让给文字**。这就是"一屏一个焦点"的具体执行。

空态那一句问候是唯一允许的"情绪化文案"，且每次启动随机从 6 条里选，不要天天一样。

### 3.2 悬浮球（agent 模式）

直径 **84px**，无边框、置顶、可拖动、自动吸附屏幕边缘。

```
        ┌──────────────────────────────────┐
        │ ● 正在打开记事本                  │   ← 气泡：当前动作
        │   已启动 notepad.exe              │
        └──────────────────────────────────┘
              ┌────────────────────────────┐
              │ ✓ 模型切换完成 3.4s         │   ← 气泡：刚完成
              └────────────────────────────┘
                        ╭─────╮
                        │  ◍  │              ← 球体
                        ╰─────╯
```

- 球心是 56px 莫比乌斯，外圈 1px 描边 + **不定长扫描弧**（90° 段落，2.4s 转一圈）
- **不显示百分比**——agent 的"进度"没有可靠分母，用扫描弧表达"在动"
- 悬停 200ms 弹出迷你面板：当前档位 / 模型 / 停止按钮
- 双击展开主窗口
- 拖动时降低不透明度到 0.85，松手回弹到吸附位置

**常驻策略**（已定：**常驻桌面**）

球一直在，所以它必须"存在但不打扰"。四条规则：

| 场景 | 行为 |
| --- | --- |
| 空闲 > 60s | 不透明度降到 0.55，转速降到 0.06 rad/s（几乎静止） |
| 空闲 > 5min | 动画停表，只保留静止轮廓（省电，笔记本友好） |
| 鼠标移入 | 250ms 恢复到 1.0 不透明度，转速恢复 |
| 主窗口打开时 | 球自动淡出（避免两个焦点打架），关窗后回来 |

其他：

- 拖动时 0.85 不透明度，松手回弹吸附到最近边缘
- 位置记在配置里，下次启动原位
- **全局热键**（默认 `Ctrl+Alt+E`）唤出/隐藏，随时能躲开
- 球永远不抢焦点（`Tool` 窗口 + `WA_ShowWithoutActivating`），点它不打断你正在打的字
- 右键菜单：打开主窗 / 静音 / 停止当前任务 / 退出

### 3.3 气泡：怎么"汇报进度"

气泡是唯一的信息出口，规则要严：

| 属性 | 规则 |
| --- | --- |
| 位置 | 球上方 12px，从下往上堆叠 |
| 数量 | 最多 3 条，新的顶掉最旧的 |
| 宽度 | 自适应，最大 320px |
| 结构 | 状态点 + 标题（13px）+ 详情（11px，最多 2 行） |
| 出现 | 220ms，淡入 + 上移 8px |
| 消失 | 180ms 淡出；鼠标悬停时暂停消失 |
| 内容 | 来自 agent 事件，**不编造** |

气泡说三类话：
1. **正在做**："正在打开记事本" / "正在读取 config.toml"
2. **刚做完**："✓ 已启动，窗口就绪" / "✓ 写入 128 行"
3. **要求你**："⚠ 需要你确认：允许执行 shell 命令？"（带两个按钮）

**不要**说："已完成 60%"。

### 3.4 展开的任务面板（点击气泡或球）

```
┌────────────────────────────────┐
│ ◍ 桌面操作 · 执行中             │
│ ─────────────────────────────  │
│ ✓ 启动记事本                    │
│ ● 激活窗口（无标题 - Notepad）  │
│                                │
│            [ 停止 ]   [ 展开 ]  │
└────────────────────────────────┘
```

只列**已发生**和**正在发生**的步骤。模型如果自己输出了计划，才把后续步骤显示为 `○ 待执行`——不预填。

## 4. 动效规范

| 场景 | 时长 | 缓动 |
| --- | --- | --- |
| 元素出现 | 220 ms | OutCubic `(0.16, 1, 0.3, 1)` |
| 元素消失 | 180 ms | InCubic |
| 状态切换（环的形态变化） | 320 ms | InOutSine |
| 呼吸 / 循环 | 1.8–4 s | InOutSine |
| 悬停反馈 | 150 ms | OutCubic |

铁律：

- 动效**不阻塞输入**，任何时刻都能打字、能按停止
- 不使用弹跳（bounce）、不用旋转过场、不用毛玻璃模糊（CPU 渲染扛不住）
- 同一时刻**最多两个元素**在动

## 5. 数据通道：UI 凭什么知道"在干什么"

现在 `Agent.send()` 是同步阻塞的，UI 拿不到中间过程。v0.5 必须先补这层：

```
Agent / RuntimeManager
        │  事件（回调或 Qt Signal）
        ▼
   EventBus ──> 状态机 ──> 莫比乌斯 + 气泡 + 任务面板
```

事件类型：

| 事件 | 携带 | UI 反应 |
| --- | --- | --- |
| `engine_starting` | model_id | 环 → `boot`，气泡"正在加载模型" |
| `engine_ready` | 耗时 | 环 → `idle`，气泡"✓ 3.4s 就绪" |
| `thinking` | — | 环 → `thinking` |
| `tool_start` | 工具名、参数摘要 | 气泡"正在 X"，环 → `acting` |
| `tool_end` | 成功/失败、摘要 | 气泡"✓ X"，失败则变黄 |
| `step` | 第几步 | 任务面板加一行 |
| `reply_done` | 全文、耗时、tokens | 环 → `idle` |
| `error` | 消息 | 环 → `error`，气泡红色 |

**线程模型**：Agent 在 `QThread` 里跑，事件通过 `Signal` 回主线程，所有绘制只在主线程。这一点必须先定，否则后面全是竞态。

**流式输出**（可选，建议 v0.5.1）：需要 provider 支持 SSE。没有它也能用——"思考中"动画顶住 1–3 秒是可以接受的。

## 6. 技术选型与代价

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 框架 | **PySide6 + QWidget + QPainter** | 不用 QML：打包简单、无额外运行时、调试直观 |
| 莫比乌斯 | 纯 QPainter 路径绘制 | 每帧几百图元，CPU 足够；不碰 OpenGL（显存要留给模型） |
| 悬浮球 | `FramelessWindowHint + WindowStaysOnTopHint + Tool + WA_TranslucentBackground` | 不抢焦点、不进任务栏 |
| 气泡 | 一个 Tool 窗口承载最多 3 条 | 避免多窗口焦点问题 |
| 托盘 | `QSystemTrayIcon` | 唤出/静音/退出 |
| 打包增量 | PySide6 约 +180 MB | 需排除 `opengl32sw.dll` 等无用插件 |

**性能红线**：UI 全程 CPU 渲染，单帧绘制预算 **8ms**；8 GB 显存里模型已占约 3 GB，UI 不许抢显存。

## 7. 明确不做

- 换肤 / 自定义主题色（一种强调色走到底）
- 多会话标签页（v0.6 再说）
- 复杂图表、仪表盘、粒子特效
- 毛玻璃、动态模糊、3D 转场
- 自定义字体下载（用系统字体，省 20 MB）

## 8. 决策记录

| 项 | 决定 |
| --- | --- |
| 主色 | **青绿 `#5CE1C8`** |
| 悬浮球 | **常驻桌面**（细则见 §3.2） |
| 动效强度 | **中等** |
| 流式输出 | 放 **v0.5.1**，v0.5 先做骨架 |

### 8.1 常驻球带来的两条硬约束

1. **空闲必须真的静下来。** 常驻意味着它会一直出现在你视野边缘，一直在动的球会让人烦躁，也一直烧 CPU。所以 60s 后降速降透明度、5min 后停表，是产品要求，不是优化项。
2. **绝不能抢焦点。** `Tool` 窗口 + `WA_ShowWithoutActivating`，并且点击球体本身不触发任何全局快捷键。否则你打字打到一半，输入焦点跳到球上，这个产品就废了。

### 8.2 v0.5 的实施顺序

| 步骤 | 内容 | 为什么排这个顺序 |
| --- | --- | --- |
| 1 | **事件通道 + QThread** | UI 靠它才能知道"在干什么"，先有数据再有界面 |
| 2 | 主窗口骨架：空态莫比乌斯 + 输入框 + 消息列表 | 验证绘制性能与字体渲染 |
| 3 | 状态机接线：idle / thinking / acting / error | 让动画真正跟着 agent 走 |
| 4 | 悬浮球 + 气泡 + 托盘 + 全局热键 | 最后做，依赖前面全部就绪 |
| 5 | 模型面板（选 GGUF / 切云端 / 存 key） | 复用 v0.4 的 RuntimeManager |

流式输出（SSE）统一放到 v0.5.1，v0.5 阶段文字整段出现，用"思考中"动画顶住那 1–3 秒。
