# EVE 记忆与人格演化设计

> 目标：让伊芙记住该记的，忘掉该忘的；人格从对话里长出来，但**不由对话随意改写**。

---

## 0. 三个结论

1. **分三层**：原始对话记录 → 结构化事实（带权重）→ 人格画像（定期生成）。不是"一个越来越长的文本"。
2. **提取靠模型，准入靠代码**。4B 模型负责"找出候选事实"，能不能写进记忆由**确定性规则**决定（关键词必须出自用户原话、置信度阈值、每轮上限）。
3. **人格画像是"覆盖层"，不能覆盖底线**。"不动鼠标、不关机、关键时刻可靠"这几条永远硬编码，任何自动生成都不能改。

---

## 1. 现状与两个问题

| 现状 | 问题 |
| --- | --- |
| `prompts/chat.md` 写死 | 聊一百次也不会变，确实死板 |
| `logs/*.jsonl` 只记了摘要 | 有原始素材，但没有提炼，也没被用过 |
| 对话历史全量塞进上下文 | **没做裁剪**。8192 上下文，约 40 轮就会溢出 |

最后一条是隐藏的雷：现在每轮都把完整历史发给模型，聊久了不是"记不住"，是直接报错或静默截断。

**记性问题和上下文问题是同一个问题**，一起解决。

## 2. 三层结构

```
第 1 层  原始记录（不可变）
  .data/memory/turns-YYYY-MM.jsonl
  每轮：时间、模式、用户原话、伊芙回复、耗时

第 2 层  结构化事实（可改可删，带权重）
  .data/memory/facts.db（SQLite）
  每条：内容、类型、权重、置信度、来源轮次、创建时间、命中次数

第 3 层  人格画像（生成物）
  .data/memory/persona.md
  由第 2 层里权重最高的若干条，按模板拼成
```

为什么要分成三层：只做第 1 层就是"聊天记录"，只做第 2 层是"数据库"，
第三层才是**能塞进 prompt 的、有字数上限的画像**。

## 3. 提取管线

### 3.1 什么时候提取

| 触发 | 说明 |
| --- | --- |
| 每 5 轮 | 主路径，够密也够省 |
| 会话结束 | 补一次，抓住最后几句 |
| 空闲 60 秒 | 后台跑，不阻塞对话 |

**绝不在每轮之后立刻提取**——那是 2 倍的模型调用，而且单轮信息量太小。

### 3.2 输入

最近 5 轮对话 + 已有事实的标题列表（用来去重）。

### 3.3 输出（只允许 JSON）

```json
{
  "facts": [
    {"kind": "preference", "text": "喜欢喝冰美式", "confidence": 0.9}
  ],
  "invalidate": ["f_0231"]
}
```

`kind` 只有五种：`identity`（身份）/ `preference`（偏好）/ `habit`（习惯）/
`instruction`（对伊芙的要求）/ `event`（共同经历）。

### 3.4 四道闸门（关键）

模型给的是**候选**，下面四关全过才准入库：

| 闸门 | 规则 | 拦掉什么 |
| --- | --- | --- |
| ① 原话佐证 | fact 里的关键词必须能在**用户原话**里找到（不算伊芙的回复） | 模型把自己的话当成用户说的 |
| ② 置信度 | `confidence >= 0.6` | 猜测、含糊其辞 |
| ③ 长度与形态 | 不超过 40 字，不含"可能/大概/我觉得" | 半成品、流水账 |
| ④ 去重 | 与已有事实的相似度 > 0.85 则合并（加权）而非新增 | 同一件事记十遍 |

另外**每轮最多新增 3 条**。宁可少记，不要记脏——记忆一旦污染，会一直影响后面所有对话。

## 4. 权重怎么算

这是整套机制的命门。权重不是一个数，而是几个因子的乘积：

```
weight = 基础分(kind) × 时间衰减 × 频次加成 × 明确性 × 稳定性
```

### 基础分

| kind | 基础分 | 理由 |
| --- | --- | --- |
| `instruction` | 1.0 | 用户对伊芙的明确要求，必须遵守 |
| `preference` | 0.9 | "我喜欢/我讨厌"，长期有效 |
| `identity` | 0.85 | 名字、职业这类稳定信息 |
| `habit` | 0.6 | 反复出现的行为模式 |
| `event` | 0.4 | 某次聊过的事，容易过时 |

### 时间衰减

`exp(-天数 / 45)`，但有下限 0.25——长期事实不该因为"三个月没提"就归零。

### 频次加成

`1 + 0.3 × log(1 + 命中次数)`，上限 1.8。提三次的事情显然比提一次重要，但不会无限放大。

### 明确性

用户说"以后都""每次都要""我不喜欢"这类**强表述**时 ×1.3；随口一句 ×1.0。

### 稳定性

- 被用户确认过（"对""没错"）×1.2
- 被用户否认 → **直接删除**，不是降权（记错的偏好比没记更糟）

### 一个具体例子

> 用户第 3 次说："我不喜欢被推荐电影，以后别推了。"

- kind = instruction → 1.0
- 刚发生 → 衰减 1.0
- 第 3 次 → 1 + 0.3×ln(4) ≈ 1.42
- "以后别" → ×1.3
- 合计 ≈ **1.85** → 稳稳进画像

对比："今天看了一部电影" → event 0.4 × 衰减 0.9 × 频次 1.0 ≈ **0.36** → 只在原始记录里躺着，不进画像。

## 5. 怎么注入 prompt

### 5.1 三段式

```
[底线人格]   硬编码，~180 tokens，任何情况不变
[演化画像]   从 facts 生成，≤ 400 tokens   ← 这里才是"长出来的人格"
[当前状态]   抗议等级等临时指令，≤ 80 tokens
```

### 5.2 硬预算

画像部分**必须卡死 400 tokens**。按权重从高到低填，填满为止。超出的不注入，
但可以被"最近提到"临时顶上来。

### 5.3 冲突处理

同一件事有新旧两条（"喜欢猫" → "现在养狗了"）：
- 保留两条，新的权重更高
- 注入时只出新的那条
- 旧的标记 `superseded`，不删除（可追溯）

## 6. 画像生成的边界（最重要的一条）

自动生成的画像**只能写"偏好、习惯、称呼、共同经历"这些内容**。

**永远硬编码、不可被生成内容覆盖的：**

```
- 不动用户的鼠标键盘，不关机
- 涉及文件/命令/数据时宁可多问一句
- 不谄媚，有判断，可以拒绝
```

理由：人格是可以演化的，**底线不行**。如果某天对话里出现"你以后随便动我电脑"，
提取管线可能把它记成 instruction——那必须有代码层面的白名单挡着。

画像文件本身也要**带版本**（`.data/memory/persona.md` + `persona-history/`），
用户能回滚。

---

## 7. 顺带解决：短期上下文

写记忆的同时，把"发给模型的历史"也管起来：

| 策略 | 说明 |
| --- | --- |
| 保留最近 8 轮原文 | 语义连续性最重要 |
| 更早的压成摘要 | 每次压缩把 10 轮压成 3 行，写进 `session_summary` |
| 硬上限 | 总 prompt 不超过 3500 tokens（给生成留 4k） |

这样既不会爆窗口，也不会"聊到第 41 轮突然失忆"。

## 8. 存储与隐私

| 数据 | 位置 | 用户能做什么 |
| --- | --- | --- |
| 原始对话 | `.data/memory/turns-*.jsonl` | 查看、导出、按天删除 |
| 事实库 | `.data/memory/facts.db` | `/memory` 列出、单条删除、清空 |
| 画像 | `.data/memory/persona.md` | 查看、回滚历史版本 |

**全部本地，不上传**。命令：`/memory`（列表）、`/forget <id>`（删一条）、`/memory clear`。

## 9. 分阶段

| 版本 | 内容 | 为什么这个顺序 |
| --- | --- | --- |
| **v0.6.0** | 原始记录 + 事实库 + `/memory` + 注入 top-N 事实 | 先有"记住"这件事，画像可以晚点 |
| **v0.6.1** | 权重衰减 + 去重合并 + 上下文裁剪 | 让记忆不长毛、不爆窗口 |
| **v0.6.2** | 画像生成 + 版本历史 + 用户确认 | 最后才让"人格"自己长 |

先做 v0.6.0 的好处：**它的效果立刻可验证**——问一句"我喜欢什么"，看它答不答得上来。

## 10. 风险清单

| 风险 | 应对 |
| --- | --- |
| 4B 模型提取质量差 | 四道闸门 + 每轮上限 3 条；宁可漏记 |
| 记忆越记越多，prompt 被挤爆 | 硬预算 400 tokens + 权重淘汰 |
| 人格漂移变得"不像她" | 画像只做覆盖层；底线硬编码；可回滚 |
| 把模型自己的话记成用户说的 | 闸门①：关键词必须在用户原话里 |
| 隐私泄露 | 全本地 + 可见可删 |
| 提取开销 | 每 5 轮一次，空闲时后台跑 |
